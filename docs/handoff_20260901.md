## 3. 当前运行链路

正式 Gameplay 当前使用以下链路：

```text
模式入口
  -> ModeQuestionDirector / TowerDirector
  -> QuestionRequest
  -> QuestionCompiler
  -> QuestionCompilerEngine
  -> QuestionInstance
```

`QuestionCompiler` 是正式游戏的统一出题入口。旧 `QuestionGenerator`、`ExtendedQuestionGenerator`、`QuestionTypeCatalog`、`StaticQuestionBank` 和旧静态加载器均已删除。

### 3.1 模式状态

- 试炼塔：保留独立的楼层/通关要求导演，由 `TowerDirector` 产生请求，再交给统一编译器。
- 好友挑战：按创建者选择的主题和规则生成；相同种子与配置可复现相同题序，不受本地历史影响。
- 无尽乱斗：超过原 60 秒阶段边界后仍可持续出题，直到生命耗尽。
- 每日主题：同一天固定随机主题；玩家每次重新开局使用不同运行种子，题目内容不同。
- 普通模式与每日模式会使用跨局事实、答案和语义签名冷却，降低短期重复。

## 4. 模板唯一模型已完成

本阶段已经删除旧题型路由体系：

- `QuestionInstance` 不再包含 `familyId` 和 `typeId`；
- `ContentFamilyKind`、`ContentFamilySpec`、`CONTENT_FAMILIES` 已删除；
- `QuestionTemplate` 是唯一题型实体；
- `QuestionCompileDirective` 直接携带选中的模板和显式难度；
- 规则兼容、目标上限和方向敏感性均由模板声明；
- `QuestionBankPack` 使用 `templateIds` 关联模板；
- 试炼塔只通过主题、能力、标签、规则和难度请求题目；
- 编译引擎按 `template.id` 路由，未知模板直接失败，不再生成兜底题；
- 算法变化使用请求中的 `difficulty`，不再用 variant 伪造多个题型。

## 5. 当前核心模型

```ts
interface QuestionTemplate {
  id: QuestionTemplateId;
  theme: ThemeId;
  engine: GameplayEngineId;
  capabilities: QuestionCapability[];
  tags: string[];
  sourceKind: 'algorithmic' | 'reviewed-facts';
  difficultyBands: DifficultyBand[];
  supportedRuleSets: RuleId[][];
  targetCap: number;
  directionSensitive?: boolean;
  enabled: boolean;
}

interface QuestionInstance {
  id: string;
  templateId: string;
  theme: ThemeId;
  engineId: GameplayEngineId;
  factIds: string[];
  contentVersion: string;
  // prompt、targets、activeRules 等运行时字段
}
```

约束：

- `theme` 是显式字段，不能从 `templateId` 字符串推断；
- `templateId` 是稳定且唯一的模板标识；
- 模式只使用 `themes + capabilities + tags + rules + difficulty` 选题；
- `factIds` 追踪素材来源；
- 正式实例必须同时携带 `templateId`、`engineId`、`factIds` 和 `contentVersion`。

## 6. 事实审核和扩充方式

- 21 个事实包统一登记在 `QuestionBankRegistry.ts`；
- 每个包显式关联 `templateIds`；
- 每个包继承来源、审核状态和审核日期；
- 审计检查模板 ID、规则声明、目标上限、重复事实和干扰项；
- 扩充现有题型时增加审核事实；新增认知动作时新增模板和对应编译算法；
- 正式V2题包和同schema fallback包由 `npm run build:questions` 确定性生成，并由manifest记录SHA-256校验值；
- 旧 8,000 条静态 JSON 已完成覆盖审计并从当前分支删除。

后续内容优化重点：

1. 为需要外部依据的常识记录补充更细粒度的来源信息；
2. 持续扩充生活、地理和历史等事实池；
3. 真机验证高压阶段的可读性、触控空间和难度曲线。
