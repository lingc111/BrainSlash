六、动态数据要求
========

下面这些内容绝对不能写死在图片里：
    Lv.12
    学徒

    120/150

    好友刚刚完成斩击！

    04:23:59

    7/10

创建一个简单的数据模型，例如：
    export interface HomeViewData {
        level: number;
        rankName: string;

        energy: number;
        maxEnergy: number;

        friendMessage: string;

        challengeEndTime: number;

        rankProgress: number;
        rankProgressMax: number;
    }

第一版可以使用 Mock 数据。

例如：
    {
        level: 12,
        rankName: '学徒',

        energy: 120,
        maxEnergy: 150,

        friendMessage: '好友刚刚完成斩击！',

        challengeEndTime: Date.now() + 4 * 60 * 60 * 1000,

        rankProgress: 7,
        rankProgressMax: 10
    }

UI Controller 根据数据刷新页面。

不要把业务逻辑散落在各个 Button 里面。

八、倒计时
=====

实现：
    04:23:59

要求：

根据：
    challengeEndTime

计算剩余时间。

格式：
    HH:mm:ss

每秒刷新一次。

不要每帧做无意义的大量计算。

倒计时结束后显示：
    00:00:00

并预留：
    onChallengeExpired()

结构：
    StartButton

    └── StartLabel

    国旗猎人

十一、屏幕适配
=======

这是非常重要的一部分。

不要简单把：

941 × 1672

整张内容 Scale 到所有设备。

采用：
    Canvas
    └── Background
    └── SafeArea

Background：

铺满整个屏幕。

SafeArea：

包含实际 UI。

使用：

* Widget

* Anchor

* SafeArea

顶部：

Header 固定在安全区顶部。

底部：

BottomNavigation 固定在安全区底部。

中间区域：

根据可用空间布局。

设计原则：
    Header
    ↓
    DailyChallenge
    ↓
    Brawl
    ↓
    Events
    ↓
    Progress
    ↓
    BottomNavigation

屏幕更长时：

增加模块之间的留白。

屏幕更短时：

适当整体压缩间距。

不要：

* 拉伸纸张比例

* 拉伸图标

* 拉伸字体

* 破坏视觉稿比例
