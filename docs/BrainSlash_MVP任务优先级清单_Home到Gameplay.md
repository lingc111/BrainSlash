# 《Brain Slash》MVP 任务优先级清单

> 当前范围：Home → Gameplay  
> 暂不包含：正式 Result 页面、Chaos、商城、养成、实时 PvP 等非 MVP 内容  
> 技术基线：Cocos Creator 3.8.8 + TypeScript

## 1. 实施原则

按“先进入游戏 → 再完整玩一局 → 再补规则和体验”的顺序开发。

- 首页图和 Gameplay 图作为视觉标尺，不作为整张背景直接承载交互。
- HUD、按钮、目标和状态提示必须拆为节点、组件或 Prefab。
- Gameplay 逻辑与视觉表现分离。
- 输入、命中判定和音效优先于粒子与装饰特效。
- Result 页面生成前，使用临时结束面板完成测试闭环。
- 每个阶段都要产出可运行版本，不等待所有规则和内容完成后再测试。

## 2. P0：工程基础与页面跳转

### 2.1 整理工程结构

- [ ] 保留现有 `Home.scene` 和 `Gameplay.scene`。
- [ ] 建立以下代码目录：
  - `app`：启动、场景流转、进入参数。
  - `domain`：题目、规则、计分、局内状态。
  - `presentation`：Home、Gameplay、通用组件。
  - `infrastructure`：存档、微信适配、音效、震动。
  - `configs`：玩法参数、规则配置和题库。
- [ ] 将颜色、字号、间距和动效时间统一放入 Design Tokens。
- [ ] 锁定 Cocos Creator 3.8.8，MVP 开发期间不升级引擎。

**验收标准：** 工程无编译错误，Home 和 Gameplay 均可独立运行。

### 2.2 跑通 Home → Gameplay

- [ ] 保留“60 秒乱斗”主按钮。
- [ ] 保留“今日挑战”入口，首版可使用固定 Seed。
- [ ] 显示本地最高分，暂无数据时使用默认值。
- [ ] 完成微信胶囊、状态栏和顶部安全区避让。
- [ ] 点击按钮时传递 `mode`、`seed`、`contentVersion`。
- [ ] 加载 `Gameplay.scene`。
- [ ] 防止连续点击造成重复切换场景。

**验收标准：** 点击首页主按钮后能稳定进入 Gameplay，并正确读取开局参数。

## 3. P0：一局可玩的最小纵切

### 3.1 建立局内核心数据

- [ ] 定义 `GameSessionState`：
  - 剩余时间；
  - 生命；
  - 分数；
  - Combo；
  - 当前题目；
  - 当前阶段。
- [ ] 定义 `QuestionInstance`：
  - 提示文本；
  - 目标列表；
  - 正确目标 ID；
  - 禁止目标 ID；
  - 当前规则。
- [ ] 定义 `HitResult`：
  - 正确；
  - 错误；
  - 炸弹；
  - 漏斩；
  - Master Hit。
- [ ] HUD 只读取和显示状态，不自行计算玩法结果。

**验收标准：** 局内数据不再散落在 `GameplayHUD` 中，玩法状态存在唯一数据来源。

### 3.2 实现局内状态机

```text
Ready
→ 生成题目
→ 等待斩击
→ 判定结果
→ 播放短反馈
→ 下一题
→ 时间结束或生命归零
→ 临时结束
```

- [ ] 实现 60 秒倒计时。
- [ ] 实现 3 点生命。
- [ ] 处理暂停和切后台。
- [ ] 恢复游戏前显示约 600ms `READY`。
- [ ] 游戏结束后停止输入、计时和目标生成。

**验收标准：** 一局可从开始稳定运行到时间结束或生命耗尽。

### 3.3 先实现单一题型

首个纵切只实现：

- [ ] 主题：简单心算或数字判断。
- [ ] 规则：标准规则。
- [ ] 目标数量：2–3 个。
- [ ] 运动方式：低速、可预测。
- [ ] 正确答案：1 个。
- [ ] 错误答案：1–2 个。

**验收标准：** 连续游玩 5 局，不出现无解题、重复结算或目标重叠。

### 3.4 实现目标生成与回收

- [ ] 建立通用 `GameplayTarget` Prefab。
- [ ] 支持文字、数字和图形内容接口。
- [ ] 将目标视觉尺寸与命中体分离。
- [ ] 目标避开 HUD、微信胶囊和底部手势区。
- [ ] 初始生成位置不能重叠。
- [ ] 实现目标移动、离场和回收。
- [ ] 使用对象池，避免频繁创建和销毁节点。
- [ ] 原始 1254×1254 目标图片保留归档，运行时使用缩放、压缩后的版本。

**验收标准：** 连续生成目标时无明显卡顿、残留节点或碰撞体泄漏。

### 3.5 实现连续划动判定

这是 MVP 的最高风险功能，应早于复杂视觉特效完成。

- [ ] 监听 `TOUCH_START / MOVE / END / CANCEL`。
- [ ] 将触点转换到 Gameplay 本地坐标。
- [ ] 记录上一采样点到当前采样点的连续线段。
- [ ] 检测线段与目标命中体是否相交。
- [ ] 对高速划动进行插值，避免穿透。
- [ ] 同一手势内，同一目标只命中一次。
- [ ] 按实际轨迹保存目标命中顺序。
- [ ] 将判定轨迹与刀光渲染分离。

**验收标准：** 快速划过目标也能稳定命中，不能只在触点终点生效。

### 3.6 完成基础结算

- [ ] 正确：加分，Combo +1。
- [ ] 错误：生命 -1，Combo 清零。
- [ ] 漏斩：生命 -1，Combo 清零。
- [ ] 生命为 0 时结束游戏。
- [ ] 时间为 0 时结束游戏。
- [ ] Master Hit 首版按反应时间窗口判断。
- [ ] 分数、倍率和时间阈值全部配置化。

Result 页面完成前：

- [ ] 使用临时结束面板显示本局分数。
- [ ] 提供“再来一局”。
- [ ] 提供“回到首页”。
- [ ] 不制作正式 Result 视觉和数据布局。

**验收标准：** 分数、生命和 Combo 数据与 HUD 始终一致。

## 4. P1：基础反馈和操作手感

### 4.1 接入最小反馈链

正确斩击：

- [ ] 触摸后立即显示刀轨。
- [ ] 播放切割音效。
- [ ] 播放目标切开效果或替换为切割图。
- [ ] 生成少量碎片。
- [ ] 显示分数浮字。
- [ ] 播放 Combo 增长动效。
- [ ] 触发轻震。

错误斩击：

- [ ] 局部 Danger 色短闪。
- [ ] 触发 80–120ms 震动。
- [ ] 更新生命显示。
- [ ] 播放 Combo 断裂反馈。
- [ ] 播放低频错误音。

Master Hit：

- [ ] 触发 80–150ms hit stop。
- [ ] 使用更强刀光。
- [ ] 显示 Highlight 色分数浮字。
- [ ] 总反馈在 300–450ms 内退出。

**验收标准：** 反馈不遮挡下一题，也不延迟下一次输入。

### 4.2 完善 HUD 数据绑定

- [ ] 左上显示 Combo。
- [ ] 顶部中央显示当前提示。
- [ ] 提示下方持续显示 RuleBadge。
- [ ] 右上显示倒计时和生命。
- [ ] 中央只保留目标、刀轨和短时反馈。
- [ ] Gameplay 底部不设置传统操作按钮。

**验收标准：** 玩家能在 0.5 秒内识别提示和规则，HUD 不挤压中央操作区。

## 5. P1：六类规则

按以下依赖顺序实现。

### 5.1 炸弹／禁区

- [ ] 建立 `forbiddenTargetIds`。
- [ ] 命中炸弹后立即扣除生命。
- [ ] 使用形状、图标和轮廓共同区分炸弹。
- [ ] 炸弹命中体可比视觉体缩小约 8%。

### 5.2 多目标

- [ ] 建立 `requiredTargetIds`。
- [ ] 一笔命中全部必斩目标后才判定成功。
- [ ] 未命中全部目标时不能提前结算成功。

### 5.3 顺序

- [ ] 建立 `orderedTargetIds`。
- [ ] 按斩击轨迹记录命中顺序。
- [ ] 顺序错误时立即判定失败。

### 5.4 反向

- [ ] 翻转普通目标的正确集合。
- [ ] 炸弹永远不能被翻转为正确目标。
- [ ] RuleBadge 在反向状态期间持续显示。
- [ ] HUD 边缘持续显示反向状态视觉。
- [ ] 切换前提供 0.8–1.2 秒预警。

### 5.5 Stroop

- [ ] 将内容含义与显示属性分离。
- [ ] 提示明确采用哪一个判断维度。
- [ ] 保证答案唯一。
- [ ] 避免普通语义色和 Stroop 颜色产生歧义。

### 5.6 规则通用要求

- [x] 每种复杂规则首次出现时插入无惩罚教学题。
  - 首次只保留一个未掌握规则，目标数最多 4 个、题时至少 3.4 秒、速度最多 0.76。
  - 使用 HUD 下方单行短提示持续说明动作；失败不扣命、不断 Combo、不计错误，并重置同一题后原题重试。
- [ ] 每题最多组合两个复杂规则。
- [ ] 建立允许的规则组合白名单。
- [ ] 为每种规则及允许组合建立固定 Seed 回归测试。

## 6. P2：内容、难度与首页完善

### 6.1 三阶段难度

| 时间 | 目标数量 | 规则 | 运动策略 |
|---|---:|---|---|
| 0–15 秒 | 2–3 | 标准规则为主 | 低速、间距大 |
| 15–40 秒 | 3–5 | 单个复杂规则 | 中速、可预测交叉 |
| 40–60 秒 | 通常 4–5；纯视觉单规则可到 6 | 最多两个复杂规则，双规则减 1 个目标 | 提速但保持公平，不持续自转 |

- [ ] 难度只通过配置调整。
- [ ] `DifficultyDirector` 不直接操作 HUD。
- [ ] 速度提升不能降低命中公平性。
- [ ] 竖屏阵型每行最多两个目标：4 个 `2×2`、5 个 `2+1+2`、6 个 `2×3`。
- [ ] 文字与数字目标只允许短暂入场倾斜，180–240ms 内回正，禁止持续自转。

### 6.2 扩充最小题库

按以下顺序扩充：

1. [ ] 心算／数字；
2. [ ] 眼力／形状；
3. [ ] 汉字／成语；
4. [ ] 英语；
5. [ ] 生活常识；
6. [ ] 国旗／地理。

每新增一个主题，必须同时完成：

- [ ] 内容配置；
- [ ] 干扰项生成；
- [ ] 答案唯一性检查；
- [ ] 图片缺失检查；
- [ ] 固定 Seed 回归；
- [ ] 连续游玩 5 分钟防重复测试。

### 6.3 首页真实数据

- [ ] 今日挑战按日期生成固定 Seed。
- [ ] 显示本地最高分。
- [ ] 显示单一轻量等级或进度。
- [ ] 读取分享参数并显示好友挑战入口。
- [ ] 首次进入时突出主 CTA。
- [ ] 不增加商城、任务大厅和多货币入口。

## 9. 当前范围完成定义

Home → Gameplay 阶段同时满足以下条件，才算完成：

- [ ] 首页可稳定进入 60 秒乱斗。
- [ ] 开局参数可正确传递到 Gameplay。
- [ ] 一局可因时间结束或生命归零而正常停止。
- [ ] 快速划动使用连续线段判定，无明显穿透。
- [ ] 六类规则均可通过配置生成和判定。
- [ ] 反向状态在持续期间始终清晰可见。
- [ ] 炸弹不会被反向规则变成正确目标。
- [ ] 正确、错误、Combo 和 Master Hit 反馈短促清晰。
- [ ] 中央斩击区域不被 HUD 或反馈遮挡。
- [ ] 微信胶囊、刘海、状态栏和底部手势区无遮挡。
- [ ] 连续游玩 10 局无明显掉帧、资源泄漏或状态错误。
- [ ] 临时结束面板可以重新开始或返回首页。
- [ ] Chaos 和正式 Result 页面没有进入当前依赖链。
