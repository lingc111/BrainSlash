# Brain Slash 项目指令

## 项目定位

本项目是一款手机竖屏微信小游戏，工作名为《脑斩 / Brain Slash》。核心体验是：

观察提示 → 理解规则 → 判断目标 → 手指斩击 → 即时反馈。

产品首先必须像一款高速、爽快的街机动作游戏，而不是教育 App、传统答题游戏或儿童学习软件。

## UI 与 UX 工作前置要求

进行以下任何工作前，必须完整阅读并遵守根目录中的 `微信小游戏_UI设计总提示词_v1.1.md`：

- UI、UX、页面布局或交互设计；
- Gameplay HUD、首页或结算页设计；
- 视觉风格、Design System、组件或图标设计；
- 动效、音效、震动与 Game Feel 设计；
- UI 图片、概念图或视觉生成提示词；
- Cocos Creator UI、触屏操作、安全区或适配实现。

如果详细提示词与本文件存在冲突，以本文件和用户当前明确要求为准。

## MVP 范围

优先完成以下闭环：

首页 → Gameplay → Result → 再来一局或挑战好友。

除非用户明确要求，不主动增加商城、抽卡、宠物、复杂角色养成、签到大厅、任务大厅、公会或实时 PvP。

MVP 首发规则包括：

- 标准；
- 反向；
- 多目标；
- 顺序；
- Stroop；
- 炸弹 / 禁区。

Chaos 是扩展机制，不是原 PRD v1.0 的既定 MVP 功能。涉及 Chaos 时应明确标注这一点，且不得让它影响基础规则识别、操作公平性或触屏空间。

## 不可破坏的设计原则

- 信息识别优先于装饰效果；
- 当前提示和规则应能在 0.2–0.5 秒内识别；
- 题目不能暂停或打断游戏，答案必须表现为场上目标；
- Gameplay 中央区域优先留给运动目标和连续划动；
- 反向状态必须持续可见，不能只依赖一次弹窗或单一颜色；
- 正确、错误、Master Hit 和 Combo 必须有清晰但短促的游戏反馈；
- 错误反馈不能长时间遮挡下一次判断；
- 微信胶囊按钮、刘海、灵动岛、状态栏和底部手势区必须避让；
- 不依赖 Hover，目标和控件必须适合单手触屏；
- 组件、Design Tokens 和状态语言应在三个 MVP 页面之间复用；
- 设计方案必须适合两名程序员使用 Cocos Creator 实现；
- 输入响应、命中判定和音效优先级高于粒子与装饰特效。

## 禁止方向

不得把产品设计成或包装成：

- 学习 App、课堂、学校、黑板、课本或试卷；
- 传统四选一 Quiz、答题卡或长文本知识讲解；
- 首页学科目录；
- 幼儿园式卡通教育视觉；
- UI 拥挤、目标过小、过量霓虹或重度 3D；
- Gameplay 底部传统操作栏；
- 依赖复杂人物插画或大型实时 3D 场景的 MVP。

## 实现约束

- UI 使用可复用 Prefab 和统一 Design Tokens；
- 页面适配使用 Canvas、UITransform、Widget 与安全区逻辑；
- 微信右上角胶囊区域必须根据运行时信息动态避让；
- 规则、HUD 和 Chaos 状态由集中状态机驱动，避免散落硬编码；
- 运动目标、碎片、刀光和浮字优先使用对象池；
- 斩击命中应按连续手势轨迹判定，不能只检测触点终点；
- 低端设备优先降低粒子、拖尾和背景效果，不能牺牲输入响应和音效时机。

## 输出要求

设计页面时必须具体说明元素的位置、尺寸层级、信息优先级、状态变化、动效时长和 Cocos Creator 实现方式，不使用“漂亮、现代、高级、有游戏感”等无法执行的空泛描述。

生成视觉提示词时，必须同时给出 Negative Prompt，并排除教育 App、四选一答题、黑板课本、复杂人物插画、拥挤 UI、微小目标、文字乱码、过量霓虹、重度 3D、Gameplay 底部操作栏和非 MVP 入口。
