# 《脑斩 / Brain Slash》统一题库与出题系统重构方案

> 文档状态：待评审
> 适用阶段：未发布版本，允许破坏式重构
> 核心原则：不保留旧题序、旧题型 ID 或旧题包兼容；保留并接入当前试炼塔 50 层逐层独立挑战设计。

## 1. 背景

当前题目系统已经具备确定性随机、规则组合、题目冷却、静态资源加载和试炼塔专项题池等基础能力，但内容生产与运行时出题存在多条并行路径：

1. `resources/question-banks` 中的静态成品题；
2. `ExtendedQuestionGenerator.ts` 中硬编码的扩展题型和小型关系表；
3. 静态资源加载失败或不适配时使用的旧生成器；
4. 少量 V2 结构化内容包。

这些路径使用不同的数据结构、题型标识、干扰项策略和审核标准，使题目来源难以追踪，题型调度与实际内容不能稳定对应。

已发现的直接问题包括：

- `氧气—气体` 同时作为题干和正确答案；
- `食物：金鱼` 使用不完整的问句配合“是/否”答案；
- 交通工具在小型兜底池和固定 seed 下反复出现相同答案组合；
- 生成器在候选不足时使用“其他”“都不是”“无法判断”补足目标；
- 多个题型名称对应同一固定模板或极小内容池；
- 当前结构审计可以证明题目不会崩溃，但不能证明事实正确、语义清晰或干扰项合理。

因此，本轮不再逐题修补，而是统一重构题库模型、题型模型、出题入口、模式请求和质量门禁。

## 2. 重构目标

### 2.1 总体目标

最终只保留一条正式出题链路：

```text
游戏模式提出 QuestionRequest
→ 统一题型目录筛选 Template
→ 选择审核 Fact 或生成算法参数
→ 生成候选 QuestionInstance
→ 结构、语义与规则校验
→ 冷却与去重
→ 返回可玩题目
```

### 2.2 必须达到的结果

- 所有模式使用同一个题型目录和同一个出题入口；
- 每道题都能追踪到稳定的 `templateId`、`factIds` 和内容版本；
- 题型负责认知动作和生成规则，素材负责事实，不再混写；
- 数学、视觉使用受审计的程序化模板；
- 英语、汉字、生活、地理、常识、历史使用审核事实；
- 静态题包仅作为统一模型的构建产物，不再拥有独立出题逻辑；
- 内置 fallback 与正式题包使用相同 schema 和校验规则；
- 试炼塔按题型能力和内容标签选题，不再依赖含义模糊的旧 `familyKind`；
- 删除扩展概率旁路、旧题型轮转和自动补伪选项逻辑；
- 题库数量不再作为主要质量指标，改为统计真实模板、审核事实和有效实例覆盖率。

### 2.3 不作为本轮目标的内容

- 不重写斩击手势和命中判定；
- 不重写 Reverse、Multi、Order、Rotate、Bomb 等规则语义；
- 不改变首页、Gameplay、结算页的产品闭环；
- 不强制保留旧版本 seed 对应的题序；
- 不保留旧题型 ID、旧题包 schema 或旧楼层题池兼容层。

## 3. 当前系统的结构性问题

### 3.1 多条出题路径产生行为分叉

静态题、扩展题和旧生成器可能针对同一个主题生成完全不同的题目。修复其中一条路径不能保证问题不会从另一条路径再次出现。

### 3.2 题型目录与实际生成能力不一致

当前题型数量包含大量名称变化、固定答案和极小模板。题型数量不能代表实际内容丰富度。重构后只有认知动作、题干结构或干扰策略存在实质差异时，才定义为独立题型。

### 3.3 通用关系表承载过多语义

生活主题使用单条记录同时描述分类、垃圾、交通、食物、植物、动物、职业、地点、天气、季节、用途和来源，字段之间缺少明确语境，容易生成牵强或有争议的问题。

### 3.4 静态题缺少精确题型信息

现有静态题主要依赖 `familyKind`，不能准确表达具体模板、答案域、规则兼容性和能力标签，导致模式选择了某种题型族，却不一定获得对应认知动作的题目。

### 3.5 审计范围不足

当前审计集中在数量、格式、重复、长度和目标集合合法性，缺少语义泄露、答案域、干扰项质量、内容来源和题型覆盖检查。

## 4. 目标架构

### 4.1 核心对象

```text
Theme
└─ QuestionTemplate
   ├─ CapabilityProfile
   ├─ DifficultyBands
   ├─ PromptPolicy
   ├─ AnswerPolicy
   ├─ DistractorPolicy
   └─ FactQuery / Algorithm
      ↓
QuestionCompiler
      ↓
QuestionInstance
```

### 4.2 题型模板

建议定义：

```ts
interface QuestionTemplate {
  id: string;
  theme: ThemeId;
  family: string;
  engine: GameplayEngineId;
  capabilities: QuestionCapability[];
  sourceKind: 'algorithmic' | 'reviewed-facts';
  promptPolicy: PromptPolicy;
  answerPolicy: AnswerPolicy;
  distractorPolicy: DistractorPolicy;
  difficultyBands: DifficultyBand[];
  supportedRuleSets: RuleId[][];
  enabled: boolean;
}
```

只有以下任一项存在实质差异时，才建立新模板：

- 玩家执行的认知动作不同；
- 题干结构不同；
- 答案关系不同；
- 干扰项生成策略不同；
- 对规则组合的兼容性不同。

仅改变数字范围、目标数量、速度或难度，不建立新模板。

### 4.3 能力标签

建议第一版能力集合：

```ts
type QuestionCapability =
  | 'single'
  | 'multi'
  | 'order'
  | 'reverse'
  | 'rotate'
  | 'bomb'
  | 'master-slash'
  | 'stroop'
  | 'category'
  | 'numeric'
  | 'short-text';
```

能力标签用于：

- 模式筛选题型；
- 试炼塔专项题池；
- 规则兼容检查；
- 内容覆盖统计；
- 构建时可完成性验证。

能力必须由模板声明，不能由运行时根据题目结果猜测。

### 4.4 审核事实

建议统一事实结构：

```ts
interface FactRecord {
  id: string;
  kind: string;
  fields: Record<string, string | number | boolean>;
  tags: string[];
  source: string;
  reviewStatus: 'draft' | 'reviewed' | 'blocked';
  reviewedAt: string;
  enabled: boolean;
}
```

不同语义关系使用不同 `kind` 和字段约束，禁止重新建立无类型的通用关系大表。

示例：

```json
{
  "id": "life.transport.train",
  "kind": "item-category",
  "fields": {
    "item": "火车",
    "category": "交通工具"
  },
  "tags": ["transport", "rail"],
  "source": "internal-reviewed-catalog",
  "reviewStatus": "reviewed",
  "reviewedAt": "2026-09-01",
  "enabled": true
}
```

### 4.5 统一题目请求

所有模式只产生需求，不决定数据来源：

```ts
interface QuestionRequest {
  themes?: ThemeId[];
  requiredCapabilities?: QuestionCapability[];
  forbiddenCapabilities?: QuestionCapability[];
  requiredTags?: string[];
  rules: RuleId[];
  difficulty: 1 | 2 | 3 | 4 | 5;
  targetCount: number;
}
```

统一出题器负责：

1. 找到满足主题、能力、标签、难度和规则要求的模板；
2. 从模板关联的审核事实或算法参数中无放回抽取；
3. 生成答案和同域干扰项；
4. 运行结构与语义校验；
5. 应用事实、答案和题面冷却；
6. 返回 `QuestionInstance`。

## 5. 各类内容的生产策略

### 5.1 数学

数学采用程序化模板，不预先堆积大量仅参数不同的静态成品题。

建议保留的真实模板包括：

- 加、减、乘、整除；
- 奇偶、倍数、因数、区间和组合条件；
- 最大、最小、接近目标；
- 等差、等比、交错和递增步长规律；
- 填空；
- 选择目标算式；
- 两数配对；
- 数字或算式排序。

每个模板必须独立定义参数边界、答案唯一性和干扰项算法。

### 5.2 视觉

视觉采用程序化模板，并要求固定 seed 截图回归。

建议保留：

- 方向与反方向；
- 数量识别；
- 唯一异类；
- 符号匹配；
- 交替、旋转和分组规律；
- Stroop；
- 镜像和对称；
- 视觉排序。

不允许不同题型复用同一固定符号答案冒充内容规模。

### 5.3 汉字与英语

采用“审核词库 + 模板”：

- 成语填空、成语顺序、反义词、近义词；
- 英语词义、分类、反义、拼写和短配对。

错字、同音字、词义和干扰项必须逐条审核。

### 5.4 生活

生活主题按明确关系拆包：

- `item-category`：物品分类；
- `item-use`：物品用途；
- `item-place`：常见场所；
- `public-sign`：公共图标；
- `safe-behavior`：明确安全行为；
- `daily-process`：生活流程；
- `time-scene`：时间与场景。

禁止：

- `食物：金鱼` 一类缺少问句的布尔题；
- 动物是否属于食物等依赖文化或语境的判断；
- `某物匹配什么` 一类关系不明确的题干；
- 天气、季节、职业等弱关联强行配对；
- 使用通用兜底选项补足候选。

### 5.5 地理、常识与历史

按关系类型拆分：

- 国家—首都、大洲、货币；
- 河流—地区、山脉—地区；
- 动物—栖息地、食物、分类；
- 植物—特征；
- 器官—功能；
- 物质—物态；
- 能源—类型；
- 人物—事件、发明；
- 历史事件—年代、顺序。

每种关系拥有独立答案域和干扰项池。事实必须包含来源和复审日期。

## 6. 干扰项策略

### 6.1 基本要求

- 干扰项与答案必须属于同一语义域；
- 不能通过文字长度或排版暴露答案；
- 不得形成第二个合理答案；
- 不得依赖地区、年代、方言或专业语境排除；
- 不得使用“其他”“都不是”“无法判断”补数量；
- 候选不足时，该模板本次生成失败并重新选题。

### 6.2 布尔题

布尔题必须显示完整问句，且候选固定为两个：

```text
题干：金属通常能导电吗？
目标：是 / 否
```

布尔题不能为了满足目标数量要求扩展到 3–5 个选项。模式请求的 `targetCount` 必须受模板能力约束。

### 6.3 多目标题

多目标题必须从事实关系中自然产生多个正确答案，禁止将普通单选干扰项提升为正确答案。

## 7. 试炼塔改造原则

### 7.1 保留当前逐层独立设计

试炼塔继续保留当前 50 层各自不同的通关要求，不改成按大阶段重复目标的结构。

当前关键节奏保持：

- 第 1–6 层：标准、多选、顺序、反向、旋转教学及单规则综合；
- 第 7 层：双规则初见；
- 第 8 层：首次 Master Slash；
- 第 9 层起：配额、连击、限时、低失误、零炸弹、零漏题、主题专项、规则专项和综合挑战逐层变化；
- 第 50 层：双规则、高难题、连击与低失误综合终局。

### 7.2 只替换题池表达方式

当前通过 `familyKinds` 筛选的题池改为能力和标签筛选：

```ts
interface TowerQuestionPool {
  themes?: ThemeId[];
  requiredCapabilities?: QuestionCapability[];
  forbiddenCapabilities?: QuestionCapability[];
  requiredTags?: string[];
  allowedRuleSets: RuleId[][];
}
```

示例：

```ts
const STROOP_POOL = {
  themes: ['vision'],
  requiredCapabilities: ['stroop'],
  allowedRuleSets: [['standard'], ['bomb']]
};

const HANZI_ORDER_POOL = {
  themes: ['hanzi'],
  requiredCapabilities: ['order'],
  allowedRuleSets: [['order'], ['bomb', 'order']]
};

const CATEGORY_MASTER_POOL = {
  themes: ['english', 'life'],
  requiredCapabilities: ['category', 'multi', 'master-slash'],
  allowedRuleSets: [
    ['multi'],
    ['bomb', 'multi'],
    ['multi', 'reverse'],
    ['multi', 'rotate']
  ]
};
```

### 7.3 当前专项层的映射

| 当前楼层 | 当前挑战 | 重构后的题池条件 |
|---:|---|---|
| 7 | 双律初见 | 支持指定双规则组合 |
| 8 | 一笔制敌 | `multi + master-slash` |
| 9 | 双律配额 | 双规则池与单规则池分别计数 |
| 14 | 色彩连斩 | `vision + stroop` |
| 22 | 汉字成序 | `hanzi + order` |
| 23 | 英语归类 | `english + category + multi` |
| 27 | 分类一笔 | `english/life + category + multi + master-slash` |
| 34 | 四域巡礼 | 数学、英语、地理、历史主题配额 |
| 44 | 博闻强记 | 常识、历史主题配额并禁止漏题 |
| 50 | 塔巅试炼 | 双规则、高难度、连击与失误限制 |

### 7.4 通关数值处理

第一轮接入新题库时保留当前各层：

- 答题数量；
- 配额数量；
- 连击要求；
- Master Slash 次数；
- 时间限制；
- 最大失误数；
- 炸弹和漏题限制。

接入后根据真机试玩和自动模拟逐层校准。只调整存在明显难度偏差的单层，不整体覆盖当前关卡设计。

## 8. 质量门禁

### 8.1 Schema 校验

- ID、模板引用和字段完整；
- `templateId`、`factId` 全局稳定且唯一；
- 主题、答案域、难度和标签合法；
- 内容状态必须为 `reviewed` 且 `enabled`；
- 来源和复审日期完整；
- 题包版本、记录数和校验和正确。

### 8.2 语义校验

以下情况构建直接失败：

- 题干等于答案；
- 非填空、规律或合法提示题中，题干完整泄露答案；
- 正确答案进入干扰项；
- 同题目标重复；
- 同题存在两个合理答案；
- 干扰项跨答案域；
- 布尔题出现两个以上非炸弹候选；
- 出现“其他”“都不是”“无法判断”等禁止候选；
- 生活题存在明显语境、地区或文化歧义；
- 事实关系冲突。

### 8.3 规则校验

- 普通单选恰好一个正确目标；
- Multi 至少两个正确目标；
- Order 顺序完整、唯一且覆盖所有必斩目标；
- Reverse 后正确集合非空；
- Bomb 永远不是正确目标；
- 旋转规则不用于方向敏感或不可读长文本；
- Master Slash 题存在自然连续斩击路径；
- 目标数量符合模板上限。

### 8.4 覆盖率校验

每个上线模板必须达到：

- 审核内容模板至少 20 个有效实例；
- 程序化模板至少通过 100 个固定 seed；
- 声明的每个难度档均有内容；
- 声明的每个规则组合均可生成；
- 任何主题连续游玩 5 分钟不出现同签名题；
- 模式与试炼塔要求的能力池均不为空。

### 8.5 试炼塔校验

每次题库构建执行：

- 50 层逐层配置校验；
- 每层题池非空；
- 每个配额 lane 都有合法题源；
- 50 层 × 1000 seed 可生成性回归；
- Master Slash 层必定生成多目标题；
- 顺序层必定生成合法顺序题；
- 限时层统计理论答题时间；
- 不允许通过放宽唯一答案或规则公平性完成生成。

## 9. 题型规模建议

不再以 201 个题型为目标。建议首个统一版本控制在 58–78 个真实模板：

| 主题 | 建议真实模板数 |
|---|---:|
| 数学 | 12–16 |
| 视觉 | 10–14 |
| 汉字 | 6–8 |
| 英语 | 6–8 |
| 生活 | 6–8 |
| 地理 | 5–7 |
| 常识 | 8–10 |
| 历史 | 5–7 |

模板数量必须以认知动作和生成策略计算，不能把难度参数、候选排列或数值范围当作新题型。

## 10. 实施阶段

### 阶段 A：建立新骨架

- 定义 `QuestionTemplate`、`QuestionCapability`、`FactRecord` 和 `QuestionRequest`；
- 建立统一题型目录；
- 建立统一 `QuestionCompiler`；
- 建立结构、语义和规则校验接口；
- 暂不接入正式玩法。

### 阶段 B：迁移核心模板

建议顺序：

1. 数学；
2. 视觉；
3. 汉字填空与顺序；
4. 英语词义与分类；
5. 生活分类；
6. 地理；
7. 常识与历史。

每迁移一个主题，必须同时完成模板、素材、审计、固定 seed 和规则兼容测试。

### 阶段 C：重做生活与常识内容

- 拆除通用关系大表；
- 按明确关系建立独立 schema；
- 删除弱语境、争议和凑数内容；
- 为每种关系建立独立答案域和干扰项策略；
- 完成人工复审。

### 阶段 D：接入所有模式

- 乱斗改为产生统一 `QuestionRequest`；
- 每日挑战改为产生统一 `QuestionRequest`；
- 好友挑战记录内容版本并使用统一请求；
- 试炼塔题池改为能力与标签；
- 所有模式调用同一个出题入口。

### 阶段 E：重建题包

- 使用统一编译器生成正式题包；
- 生成内置安全 fallback 包；
- 增加 manifest、checksum 和记录统计；
- 验证正式包和 fallback 使用相同 schema。

### 阶段 F：删除旧系统

新链路全量通过后，直接删除：

- `ExtendedQuestionGenerator.ts`；
- 旧 `QuestionTypeRotation`；
- `legacyQuestionTypeForFamily`；
- 静态题直接选择旁路；
- 旧 fallback 生成链路；
- V1 题包 schema；
- “201 个题型”数量断言；
- 与旧题型 ID、旧题序兼容相关的代码和测试。

不长期保留双轨开关。

### 阶段 G：平衡与验收

- 运行全部领域测试；
- 运行题库构建和语义审计；
- 运行 1000 seed 混合模式回归；
- 运行 50 层 × 1000 seed 试炼塔回归；
- 对关键专项层做真机试玩；
- 按单层数据调整时间、题量或失误限制；
- 输出最终模板、事实、难度、规则和试炼塔覆盖报告。

## 11. 删除与保留边界

### 11.1 保留并复用

- `QuestionInstance` 的核心运行时语义；
- Seeded RNG；
- 事实、答案和题面冷却思想；
- Reverse、Multi、Order、Rotate、Bomb 规则判定；
- GestureResolver 和命中处理；
- Gameplay 展示和结算链路；
- 当前试炼塔 50 层逐层独立挑战设计；
- 已审核且语义可靠的英语、成语、地理、常识和历史事实。

### 11.2 重写或删除

- 201 个扩展题型目录；
- 扩展题型概率旁路；
- 无类型通用关系表；
- 通用凑数干扰项；
- 静态题与程序生成器各自独立选题的双轨逻辑；
- 静态加载失败后切换到另一套行为的旧 fallback；
- 仅验证结构、不验证语义的审计标准；
- 仅靠 variant 增加题型数量的目录结构。

## 12. 最终验收标准

重构完成必须同时满足：

1. 代码中只有一个正式生产出题入口；
2. 所有模式和试炼塔使用同一题型目录；
3. 每道题都有稳定 `templateId`、`factIds` 和内容版本；
4. 试炼塔仅按主题、能力和标签选题；
5. 当前 50 层逐层独立通关设计完整保留并通过回归；
6. 不存在自动补“其他”“都不是”“无法判断”；
7. 不存在题干直接等于答案；
8. 生活和常识不再依赖无类型通用关系大表；
9. 所有语义内容均有审核状态、来源和复审日期；
10. 所有模板达到最低实例数和难度覆盖；
11. 1000 seed 混合模式无非法题；
12. 50 层 × 1000 seed 无空题池、无非法规则组合、无不可完成关卡；
13. 正式题包与内置 fallback 使用相同 schema；
14. 旧出题链路和旧兼容代码已经删除，而不是仅关闭概率。

## 13. 实施决策

本项目尚未发布，本次采用破坏式统一重构：

- 不维护旧题型 ID；
- 不维护旧题序；
- 不维护旧题包兼容；
- 不以当前 8000 条成品题和 201 个题型作为必须保留的资产；
- 保留可靠事实和稳定玩法模块；
- 保留当前试炼塔逐层独立挑战设计；
- 新系统通过验收后一次切换并删除旧系统。
